## 固定顶点覆盖 K 个点的最小面积矩形

给定二维平面上的 `n` 个点，以及一个固定的起始点 `start = [x0, y0]`。

你需要找到一个**面积最小的矩形**，使其满足以下条件：

- 矩形的四条边必须平行于坐标轴。
- 起始点 `start` 必须是矩形的四个顶点之一。
- 矩形内部或边界上至少包含 `k` 个给定的点。
- 矩形可以向起始点的右上、右下、左上或左下任意一个方向扩展。

请返回满足上述条件的矩形的**最小面积**。

如果不存在满足条件的矩形，返回 `-1`。

**注意：**

- 矩形边界上的点视为被覆盖。
- 允许矩形的宽度或高度为 `0`，此时面积为 `0`。
- 多个坐标相同的点按照其出现次数分别计数。
- 起始点不自动计入需要覆盖的 `k` 个点，除非它也出现在给定的点集合中。

**示例 1：**

```text
输入：points = [[1,3],[2,1],[3,2],[4,4]], start = [0,0], k = 2
输出：6
解释：
以 (0,0) 为矩形左下角，选择 (2,3) 为另一个对角。

矩形覆盖：
(1,3)
(2,1)

面积 = 2 × 3 = 6

也可以选择 (3,2) 作为另一个对角，面积同样为 6。
不存在面积更小且覆盖至少两个点的合法矩形。
```

**示例 2：**

```text
输入：points = [[-1,2],[-2,1],[3,4],[2,-1]], start = [0,0], k = 2
输出：4
解释：
选择 (0,0) 为矩形右下角，(-2,2) 为另一个对角。

矩形覆盖：
(-1,2)
(-2,1)

面积 = 2 × 2 = 4
```

**示例 3：**

```text
输入：points = [[1,1],[-1,1]], start = [0,0], k = 2
输出：-1
解释：
两个点分别位于起始点的左右两侧。

由于起始点必须是矩形的一个顶点，无法构造同时覆盖两个点的合法矩形。
```

**提示：**

- `n == points.length`
- `1 <= n <= 2 * 10^5`
- `1 <= k <= n`
- `-10^9 <= points[i][0], points[i][1] <= 10^9`
- `-10^9 <= start[0], start[1] <= 10^9`
- 答案保证能够使用 `long` 类型表示。

**进阶：** 请设计一个时间复杂度为 `O(n log n)` 的算法。

## 思路

### 1. 枚举矩形的扩展方向

由于起始点必须是矩形的一个顶点，且矩形的边平行于坐标轴，因此矩形只能向以下四个方向扩展：

| 方向 | 横坐标条件 | 纵坐标条件 |
|---|---|---|
| 右上 | `x >= x0` | `y >= y0` |
| 右下 | `x >= x0` | `y <= y0` |
| 左上 | `x <= x0` | `y >= y0` |
| 左下 | `x <= x0` | `y <= y0` |

分别求出四个方向上覆盖至少 `k` 个点的最小矩形面积，最后取最小值即可。

为了避免为四个方向分别编写算法，可以通过**坐标变换，将四个方向统一转换到第一象限**。

设起始点为 `(x0, y0)`，对于任意点 `(x, y)`，定义：

```java
long dx = (x - x0) * sx;
long dy = (y - y0) * sy;
```

其中 `(sx, sy)` 的取值分别为：

```java
int[][] directions = {
    {1, 1},    // 右上
    {1, -1},   // 右下
    {-1, 1},   // 左上
    {-1, -1}   // 左下
};
```

经过变换，只有满足 `dx >= 0 && dy >= 0` 的点才可能被当前方向的矩形覆盖。

由于坐标变换只涉及平移和镜像，不改变矩形面积，因此后续只需要考虑：

> 固定矩形左下角为 `(0,0)`，在第一象限中寻找覆盖至少 `k` 个点的最小面积矩形。

### 2. 将二维问题转化为一维问题

对于第一象限中的任意点 `(x, y)`，如果矩形以原点为左下角，那么矩形由宽度 `w` 和高度 `h` 唯一确定。

某个点位于矩形内部或边界上的条件为：

$$
x \le w,\quad y \le h
$$

矩形面积为：

$$
S=w\times h
$$

因此，我们需要选择合适的 `w` 和 `h`，使得满足上述条件的点至少有 `k` 个，同时最小化面积。

**关键观察：当矩形宽度 `w` 固定时，最小的高度 `h` 等于所有满足 `x <= w` 的点中第 `k` 小的 y 坐标。**

例如，假设当前宽度范围内存在以下四个点：

```text
(1, 3)
(2, 1)
(3, 2)
(3, 5)
```

如果要求覆盖至少 `k = 2` 个点，且矩形宽度为 `w = 3`，那么所有候选点的纵坐标为：

```text
y = [3, 1, 2, 5]
```

排序后：

```text
y = [1, 2, 3, 5]
```

第 `2` 小的纵坐标为 `2`，因此矩形最小高度为：

```text
h = 2
```

对应面积：

```text
S = 3 × 2 = 6
```

如果高度小于 `2`，则只能覆盖一个点，不满足要求。

所以问题进一步转化为：

> 枚举矩形宽度 `w`，动态维护所有 `x <= w` 的点中第 `k` 小的纵坐标，计算最小面积。

此外，最优矩形的右边界一定可以移动至某个被覆盖点的横坐标，而不增加面积，因此只需要枚举给定点的横坐标，不需要枚举所有可能的宽度。

### 3. 排序 + 扫描线

按照点的 `x` 坐标从小到大排序：

```java
candidates.sort((a, b) -> Long.compare(a[0], b[0]));
```

然后从左向右扫描。

当扫描到点 `(x, y)` 时：

- 当前矩形的宽度为 `x`。
- 所有已经扫描过的点都满足横坐标不超过 `x`。
- 只需要在这些点中找到第 `k` 小的纵坐标。

如果每次都重新排序纵坐标，时间复杂度会达到 `O(n² log n)`。

因此考虑使用**大小为 k 的大顶堆**进行优化。

### 4. 大顶堆维护第 k 小元素

使用 `PriorityQueue` 维护当前已经扫描的点中**最小的 k 个 y 坐标**。

```java
PriorityQueue<Long> maxHeap =
    new PriorityQueue<>(Collections.reverseOrder());
```

对于每个新扫描到的点 `(x, y)`：

1. 将 `y` 加入大顶堆。
2. 如果堆的大小超过 `k`，删除堆顶。
3. 当堆的大小等于 `k` 时，堆顶就是当前所有纵坐标中第 `k` 小的元素。

为什么使用大顶堆，而不是小顶堆？

因为我们需要保留最小的 `k` 个元素。当堆中存在 `k + 1` 个元素时，应该删除其中最大的元素。

而大顶堆恰好可以在 `O(log k)` 时间内删除最大元素。

这样堆中始终保留当前扫描范围内最小的 `k` 个 `y`。

**注意：**

- 堆中不足 `k` 个元素时，当前宽度无法覆盖 `k` 个点，不需要计算面积。
- 当堆中有 `k` 个元素时，`maxHeap.peek()` 就是第 `k` 小的纵坐标。
- 最小矩形面积为 `x * maxHeap.peek()`。

因此，每扫描一个点，就可以更新一次答案。

## 解题代码

::: code-tabs
@tab Java

```java
import java.util.*;

class Solution {
    public long minArea(int[][] points, int[] start, int k) {
        long ans = Long.MAX_VALUE;

        long x0 = start[0];
        long y0 = start[1];

        // 枚举四个方向
        int[][] directions = {
            {1, 1},
            {1, -1},
            {-1, 1},
            {-1, -1}
        };

        for (int[] dir : directions) {
            List<long[]> candidates = new ArrayList<>();

            // 坐标变换到第一象限
            for (int[] p : points) {
                long dx = (p[0] - x0) * dir[0];
                long dy = (p[1] - y0) * dir[1];

                if (dx >= 0 && dy >= 0) {
                    candidates.add(new long[]{dx, dy});
                }
            }

            // 当前方向不足 k 个点，跳过
            if (candidates.size() < k) {
                continue;
            }

            // 按 x 坐标升序排序
            candidates.sort(
                (a, b) -> Long.compare(a[0], b[0])
            );

            // 大顶堆：维护最小的 k 个 y
            PriorityQueue<Long> maxHeap =
                new PriorityQueue<>(Collections.reverseOrder());

            // 从左向右扫描
            for (long[] p : candidates) {
                long x = p[0];
                long y = p[1];

                maxHeap.offer(y);

                // 只保留最小的 k 个 y
                if (maxHeap.size() > k) {
                    maxHeap.poll();
                }

                // 堆顶即第 k 小的 y
                if (maxHeap.size() == k) {
                    long h = maxHeap.peek();
                    long area = x * h;

                    ans = Math.min(ans, area);
                }
            }
        }

        return ans == Long.MAX_VALUE ? -1 : ans;
    }
}
```

:::

## 正确性证明

需要证明，算法能够找到所有合法矩形中的最小面积。

**1. 最优矩形的宽度可以取某个点的横坐标。**

考虑任意一个覆盖至少 `k` 个点的合法矩形，其宽度为 `w`。

设该矩形内部或边界上所有被覆盖点的最大横坐标为 `w'`。

显然有：

$$
w'\le w
$$

将矩形宽度从 `w` 缩小至 `w'`，所有原本被覆盖的点仍然位于矩形内部或边界上，同时矩形面积不会增加。

因此，一定存在一个最优矩形，其右边界经过某个给定点。

所以只需要枚举候选点的横坐标作为矩形宽度。

**2. 固定宽度时，第 k 小的纵坐标对应最小高度。**

假设矩形宽度固定为 `w`，所有满足 `x <= w` 的点的纵坐标升序排列为：

$$
y_1\le y_2\le \cdots\le y_m
$$

如果 `m < k`，则当前宽度下无法覆盖至少 `k` 个点。

否则，取：

$$
h=y_k
$$

恰好能够保证至少有 `k` 个点满足 `y <= h`。

如果选择任何小于 `y_k` 的高度，则满足条件的点不足 `k` 个，因此无法形成合法矩形。

所以 `y_k` 是当前宽度下的最小合法高度。

**3. 大顶堆能够正确维护第 k 小的纵坐标。**

算法始终在大顶堆中保留已经扫描过的最小的 `k` 个纵坐标。

插入新元素后：

- 如果堆中不足 `k` 个元素，则全部保留。
- 如果堆中超过 `k` 个元素，则删除最大的元素。

因此，堆中始终保存已扫描元素中最小的 `k` 个纵坐标。

当堆的大小为 `k` 时，堆顶是这 `k` 个元素中的最大值，也就是所有已扫描纵坐标中的第 `k` 小值。

结合前两个结论，扫描过程中计算的面积包含当前方向下的最优解。

最后枚举四个方向并取最小值，因此算法能够得到全局最小面积。

## 复杂度分析

设给定点的数量为 `n`，需要覆盖的点数为 `k`。

**时间复杂度：`O(n log n)`**

对于一个方向：

1. 遍历所有点进行坐标变换，复杂度为 `O(n)`。
2. 对符合条件的点按照横坐标排序，复杂度为 `O(n log n)`。
3. 扫描所有点，每个点最多进行一次堆插入和一次堆删除，复杂度为 `O(n log k)`。

因此单个方向的时间复杂度为：

$$
O(n\log n+n\log k)=O(n\log n)
$$

由于总共只需要枚举四个方向，属于常数倍操作，因此总时间复杂度为：

$$
\boxed{O(n\log n)}
$$

**空间复杂度：`O(n)`**

- `candidates` 最多存储 `n` 个点。
- 大顶堆最多保存 `k` 个元素。
- 其他变量只占用常数空间。

因此额外空间复杂度为：

$$
O(n+k)=\boxed{O(n)}
$$

## 易错点

### 1. 必须枚举四个方向

不能只考虑右上方向，因为起始点可以是矩形的任意一个角。

坐标变换后，需要过滤掉当前方向中不满足 `dx >= 0 && dy >= 0` 的点。

其中，位于坐标轴上的点可能同时属于多个方向，这是合法的，因为矩形边界上的点也算被覆盖。

### 2. 使用大顶堆而不是小顶堆

这里要求第 `k` 小的纵坐标，所以需要维护最小的 `k` 个元素。

大顶堆可以方便地删除这 `k` 个元素中的最大值。

```java
PriorityQueue<Long> maxHeap =
    new PriorityQueue<>(Collections.reverseOrder());
```

如果错误地使用小顶堆，并在超过 `k` 个元素时调用 `poll()`，就会删除最小元素，导致最终保留最大的 `k` 个元素。

### 3. 堆的大小必须限制为 k

```java
maxHeap.offer(y);

if (maxHeap.size() > k) {
    maxHeap.poll();
}
```

如果不删除多余元素，堆顶就会变成所有已扫描纵坐标中的最大值，而不是第 `k` 小的值。

### 4. 必须使用 long 计算面积

由于坐标范围可能达到 `10^9`，两个点的横坐标差值最大可以达到 `2 * 10^9`。

矩形面积可能达到：

$$
(2\times10^9)^2=4\times10^{18}
$$

超过 `int` 的表示范围，因此需要使用 `long` 类型。

同时，坐标差值也应该使用 `long` 计算：

```java
long dx = (p[0] - x0) * dir[0];
long dy = (p[1] - y0) * dir[1];
```

这里 `x0`、`y0` 本身就是 `long`，所以减法会按照 `long` 类型计算，不会先发生 `int` 溢出。

### 5. 区分至少覆盖 k 个点和恰好覆盖 k 个点

本题要求的是**至少覆盖 k 个点**。

即使计算出的矩形实际覆盖了超过 `k` 个点，也是合法的。

特别是当多个点具有相同的横坐标或者纵坐标时，矩形边界可能同时覆盖多个点。

不需要为了恰好覆盖 `k` 个点而排除这些点。

### 6. 注意零面积矩形

当多个点位于经过起始点的一条水平线或垂直线上时，可能只需要宽度或高度为 `0` 的矩形就能够覆盖至少 `k` 个点。

此时最小面积为 `0`，而不是 `-1`。

例如：

```text
points = [[1,0],[2,0],[3,0]]
start = [0,0]
k = 2

输出：0
```

因为可以选择从 `(0,0)` 到 `(2,0)` 的退化矩形，覆盖 `(1,0)` 和 `(2,0)`。

因此本题中应保留 `dx >= 0 && dy >= 0`，不能改为严格大于。

## 总结

本题的核心是**排序 + 扫描线 + 大顶堆维护第 k 小元素**。

整体思路如下：

1. 枚举四个扩展方向，将点通过坐标变换统一映射到第一象限。
2. 按横坐标升序排序，将二维问题转化为固定矩形宽度的一维问题。
3. 使用大小为 `k` 的大顶堆维护当前扫描范围中最小的 `k` 个纵坐标。
4. 利用堆顶得到当前宽度下的最小合法高度。
5. 计算矩形面积，更新全局最小值。

最终时间复杂度为 `O(n log n)`，额外空间复杂度为 `O(n)`。

**关键技巧：**

当题目要求动态维护**第 k 小的元素**时，可以考虑使用一个大小为 `k` 的大顶堆，保留最小的 `k` 个元素，堆顶就是当前第 `k` 小的值。

类似地，如果需要维护第 `k` 大的元素，可以使用大小为 `k` 的小顶堆。

这一技巧也经常出现在 Top K、数据流排序、扫描线和动态选择类算法题中。
